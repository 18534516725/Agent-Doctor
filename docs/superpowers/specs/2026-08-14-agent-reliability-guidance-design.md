# Agent Doctor 实时可靠性指导闭环设计

日期：2026-08-14

## 产品定位

Agent Doctor 不与 Codex、Claude Code、Cursor 竞争代码生成、任务规划、子代理、Skills、Hooks、MCP、记忆或自动化能力。它是独立于任何单一客户端的本地可靠性控制层：AI 客户端负责执行任务，Agent Doctor 负责发现失控、提供证据化指导、约束高风险动作，并独立证明任务是否真正完成。

产品的核心承诺是：

> 用户可以把编码任务交给 AI，而不必持续盯守；Agent Doctor 会在任务走偏时介入，并在结束时提供不可由执行 Agent 自行伪造的验证证据。

Token、费用、完整对话和趋势继续作为诊断证据存在，但不再是首页和产品价值的中心。

## 目标用户与核心痛点

第一阶段用户是高频使用 Codex、Claude Code、Cursor、Cline 等工具的独立开发者和小团队。他们的主要痛点是：

1. 长任务需要持续盯守，Agent 可能停滞、循环或在上下文退化后偏离原目标。
2. Agent 声称已经完成，但测试、集成、产物或用户真正要求的行为并未得到独立验证。
3. 同一个项目的约束和失败教训在不同会话或不同客户端之间不能可靠复用。
4. 用户可以看到 Token、延迟和日志，却无法把这些数据即时转化为正在运行的 Agent 可以执行的纠偏动作。

## 产品边界

### Agent Doctor 负责

- 收集跨客户端、跨会话的本地规范化证据；
- 建立不可由执行 Agent 随意修改的任务验收契约；
- 识别重复失败、无进展循环、上下文风险、修改越界和无证据完成；
- 在客户端公开的生命周期节点返回最少且可执行的指导；
- 在隔离环境运行用户授权的确定性验证；
- 只将经过验证或用户明确确认的经验升级为项目规则；
- 保持指导、权限、历史和验证结果厂商无关且本地优先。

### Agent Doctor 不负责

- 生成实现方案或替代客户端编写代码；
- 提供另一套通用聊天、任务队列、子代理或工作树界面；
- 复制客户端原生 Skills、Hooks、自动化或记忆管理；
- 根据单次异常武断判断模型或客户端优劣；
- 在没有公开稳定接口时伪造实时控制能力；
- 未经授权修改模型请求、源代码、分支或外部系统。

## 首个纵向闭环

首个版本只打通一条完整路径：

```text
任务与工具事件
    ↓
会话状态投影
    ↓
确定性指导规则
    ↓
结构化 Guidance Decision
    ↓
Hook / MCP / Skill 客户端适配器
    ↓
Agent 继续、纠偏、暂停或进入验收
    ↓
新结果回到证据存储并重新计算
```

### 1. 会话状态投影

每个活动会话维护一个轻量状态，而不是每次重新扫描完整对话：

- 当前项目、客户端、会话和任务阶段；
- 最近有效进展时间；
- 最近工具调用及结果指纹；
- 连续失败次数和错误指纹；
- 最近 Git 基线与修改范围；
- Token、上下文和延迟证据；
- 已要求与已完成的验证；
- 当前仍然有效的指导和干预记录。

状态只引用已持久化或当前 Hook 明确提供的证据。客户端无法提供的字段保持不可用。

### 2. Guidance Decision

分析引擎返回机器可读、可审计的指导：

```json
{
  "decisionId": "guidance-...",
  "sessionId": "session-...",
  "kind": "continue|advise|redirect|ask|block|verify",
  "severity": "info|warning|high|critical",
  "finding": "发现了什么",
  "evidence": ["证据引用"],
  "confidence": "exact|supported|limited",
  "instruction": "发送给 Agent 的最小可执行指导",
  "prohibitedActions": ["当前应停止的动作"],
  "verification": ["指导执行后的验证条件"],
  "expiresAt": "RFC3339 timestamp"
}
```

同一个证据指纹不会反复向 Agent 注入相同指导。指导必须带有效期，并在任务状态改变后失效。

### 3. 第一批确定性规则

首版只实现能够从现有本地证据可靠判断的四类规则：

1. **重复失败**：相同工具、参数摘要和错误指纹连续失败至少三次，返回 `redirect`；继续重复时升级为 `block`。
2. **无进展循环**：连续工具活动没有文件、Git、测试或任务状态变化，且重复访问相同目标，返回 `advise` 或 `ask`。
3. **上下文风险**：上下文持续增长、压缩临近或压缩刚发生时，生成带约束、决策、未完成项和 Git 状态的交接胶囊。
4. **无证据完成**：Agent 准备停止，但任务要求的授权验证没有成功证据，返回 `verify` 并阻止对支持 Stop Hook 的客户端宣称完成。

阈值使用保守默认值，并允许按项目配置。缺少必要证据时规则不触发，不用猜测替代。

## 客户端反馈路径

客户端能力分级决定 Agent Doctor 可以如何介入：

### Hook 完整支持

对于公开提供 SessionStart、PreToolUse、PostToolUse、PreCompact 和 Stop 等生命周期节点的客户端：

- SessionStart：注入本次任务相关的已验证约束；
- PreToolUse：检查越界或已阻断的重复动作；
- PostToolUse：记录结果并返回新的指导；
- PreCompact：生成交接胶囊；
- Stop：检查验收契约，必要时要求继续工作。

### MCP + Skill 支持

Skill 要求 Agent 在任务开始、出现连续失败、准备压缩和准备结束时调用 `get_runtime_guidance`。MCP 返回 Guidance Decision 和证据边界。该路径属于指导能力，不宣称具备不可绕过的阻断能力。

### 仅观测支持

客户端只暴露日志或代理流量时，Agent Doctor 展示实时风险和用户可复制或一键发送的指导，但不得静默篡改模型请求。未来的请求级指导注入必须单独设计、明确授权并验证不改变客户端协议语义。

## 信任与权限模式

每个项目保存一个明确的控制等级：

1. `observe`：只记录和展示；
2. `guide`：自动向 Agent 注入建议，但不阻断；
3. `guard`：可以阻断重复失败、越界动作和无证据完成；
4. `autopilot`：可以在授权命令和预算内创建检查点、运行验证、反馈修复并重试。

首次启用默认为 `guide`。升级到 `guard` 或 `autopilot` 必须由用户明确确认。项目级设置覆盖全局默认，临时会话可以降级权限。

## 独立验收

任务验收契约包含用户目标摘要、基线提交、允许修改范围、禁止动作、批准的验证命令、最大调用量和费用上限。执行 Agent 可以读取契约，但不能直接改写已经确认的要求。

完成验收在独立上下文中执行：

- 对当前工作区先采集 Git 状态和差异摘要；
- 需要重放时使用 detached worktree，不切换或覆盖用户当前分支；
- 验证命令必须是 argv 数组并匹配一次性授权计划；
- 记录退出码、持续时间、输出摘要和证据指纹；
- 检查测试文件是否被删除、跳过或明显弱化；
- 结果为 `verified`、`insufficient-evidence`、`failed` 或 `blocked`。

执行 Agent 的自然语言总结永远不能单独形成 `verified` 状态。

## 项目记忆闭环

项目经验分为候选、已验证、用户确认、停用和删除状态：

- 单次模型推断只能成为候选；
- 同类失败多次出现且证据一致，可提高候选置信度；
- 通过独立验证的修复策略可以成为已验证经验；
- 用户明确规则拥有最高优先级；
- 每条经验保留来源会话、适用路径、最近验证提交和过期条件；
- 代码或配置变化使证据失效时，经验降级为待复核，而不是永久注入。

注入上下文时只选择与当前任务和目标文件相关的少量经验，禁止把整个记忆库塞入上下文。

## 仪表盘重构

首页从数据总览改为任务控制台，信息优先级为：

1. 当前活动任务及健康状态；
2. Agent Doctor 最近的自动指导、阻断和验收动作；
3. 唯一需要用户处理的决定；
4. 已验证完成、失败和证据不足的最近任务；
5. 展开后才显示 Token、费用、完整对话和原始证据。

每个活动任务显示：客户端、项目、阶段、最近有效进展、当前风险、最新指导、控制等级和验收状态。不存在风险时不制造告警；不存在活动任务时，空状态指导用户连接一个客户端并展示可获得的控制能力。

现有页面调整为：

- `任务`：活动任务、指导和验收；
- `证据`：对话、工具、文件、测试和 Git 时间线；
- `项目经验`：候选、已验证、过期和停用规则；
- `成本`：证据详情和预算边界；
- `客户端`：观测、指导、阻断能力矩阵；
- `隐私与权限`：控制等级、验证授权、保留和删除。

“任务对比”和“效率趋势”不进入首个闭环的首页主路径，保留为后续证据分析能力。

## 错误与降级

- 指导引擎异常时客户端继续工作，Agent Doctor 明确显示已降级为观察模式；
- 数据库不可写时停止生成新的自动干预，但允许浏览旧证据；
- Hook 超时时立即放行低风险动作，高风险阻断规则使用短时本地缓存；
- MCP 断开时 Skill 不得假装已获取指导；
- 验证命令超时或环境缺失时返回证据不足，不返回验证成功；
- 同一指导注入失败不会无限重试或形成新的 Agent 循环。

## 安全与隐私

- 所有分析和规则默认在本机执行；
- 不把完整对话、源代码、凭证或绝对路径发送到额外分析模型；
- 不持久化 Authorization、Cookie、API Key 或传输凭证；
- 高风险写操作、费用扩张和外部副作用需要项目权限和精确计划授权；
- 每次自动干预记录规则版本、证据、动作、结果和撤销方式；
- 用户可以暂停指导、降级控制等级、删除经验并清除全部本地数据。

## 测试策略

1. 规则单元测试：重复失败、无进展、上下文风险、完成门禁、证据不足和去重过期。
2. 状态投影测试：乱序事件、重复事件、断线恢复、跨会话隔离和数据库迁移。
3. Hook 合约测试：各生命周期输入、允许、指导、阻断、超时和失败放行。
4. MCP/Skill 合约测试：机器可读指导、证据边界、缺失数据和客户端不调用时的能力声明。
5. 验收测试：干净 worktree、命令授权、测试弱化检测、预算上限和清理。
6. 仪表盘测试：活动任务、干预记录、唯一用户决策、控制等级和降级状态。
7. 安全测试：回环边界、令牌、Origin、凭证扫描、日志和导出不泄露内容。

## 成功指标

产品不以采集请求数或 Token 数作为北极星指标。首要指标为：

- 无需用户持续盯守且最终通过独立验收的任务比例；
- Agent Doctor 提前阻止的重复失败或失控任务数；
- Agent 自称完成但被独立验收发现失败的次数；
- 同类错误跨会话重复发生率的下降；
- 用户每周节省的盯守和返工时间；
- 指导被采纳后成功推进的比例以及误阻断率。

## 实施边界

第一轮实现只包括：会话状态投影、四类确定性规则、Guidance Decision、一个 MCP 指导工具、现有 Skill 的实时指导工作流、一个具备完整 Hook 能力的客户端适配器、Codex 的 MCP/Skill 指导路径，以及任务控制台首屏。

第一轮不包括通用多 Agent 编排、自动模型选择、远程团队服务、云端同步、模型生成式诊断、请求代理静默注入或完整历史实验平台。
