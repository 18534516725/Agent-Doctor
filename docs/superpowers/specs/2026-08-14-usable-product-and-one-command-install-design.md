# Agent Doctor 可用产品与一键安装设计

## 目标

把当前“界面完成、数据链路不完整”的版本改造成可实际使用的本地 AI 任务可靠性工具：Codex/Claude 能收到证据支持的指导，首页不会在零证据时伪装健康，费用、趋势、记忆、对比、连接和本地数据页面都能回答具体问题；用户从仓库拉取后只运行一个命令即可完成构建、安装、集成和启动。

## 产品边界

Agent Doctor 不复制 Codex 或 Claude 的代码生成、计划、子代理和工具执行能力。它只负责：观察公开接口产生的本地证据、识别失控模式、把建议反馈给代理、独立展示验证和成本事实、保存用户确认的项目知识。

Claude Code 通过 Hook 获得自动反馈及其明确支持的阻断。Codex 通过 MCP、Skill 和 Agent Doctor 管理的全局指令块获得任务检查点指导；这种指导不能宣传为强制阻断。任何客户端没有接通指导信号时，界面必须显示“尚未建立引导链路”，不能显示“正在推进”。

## 分解与实施顺序

本次改造分为三个连续但可独立验收的子项目：

1. **真实控制回路**：Codex 代理记录投影为安全事件；运行时指导有明确的 connected/degraded/unavailable 状态；中文控制级别；安装 Codex Skill 和管理式指令。
2. **有用的数据工作区**：费用、趋势、记忆、对比、连接、本地数据全部改为由真实记录驱动的任务工具。
3. **一键本地安装**：一个仓库内命令完成依赖检查、前端嵌入、Go 构建、二进制安装、客户端集成和仪表盘启动。

## 一、真实控制回路

### Codex 安全事件投影

`SaveConversationRequest` 成功后调用独立的 `OperationalProjector`。投影器只产生以下内容安全的信号：

- 请求开始、成功、失败、取消；
- 延迟是否超过本项目滚动基线；
- 工具名称、工具输入和结果的 SHA-256 指纹；
- 是否出现写入型工具、验证型工具或仅检查型工具；
- 会话是否出现连续失败、重复检查、长时间无进展；
- 请求和消息的源 ID、时间、客户端、模型公开名称、精度和来源。

原始 prompt、回复、代码、命令、路径、工具参数和工具输出不得复制到 `events`。投影必须幂等，同一请求重复保存不会重复产生事件。

投影事件进入现有 `guidance.Project` 和确定性规则引擎。每次对话保存后立即求值，并通过已有 SSE 刷新仪表盘。Codex MCP 调用 `get_runtime_guidance` 时使用同一份持久决策。

### 链路状态

新增 `GuidanceConnectionStatus`：

- `active`：当前项目存在近期兼容事件，且对应客户端具备反馈通道；
- `observing`：有数据但客户端只能观察或 MCP 尚未确认调用；
- `stale`：最后证据超过设定窗口；
- `unavailable`：没有兼容事件；
- `error`：本地存储或投影失败。

首页空状态根据链路状态显示“尚未建立引导链路”“正在观察，等待客户端查询”或“当前没有需要介入的问题”。只有 `active` 且存在健康进展证据时才能显示“正在推进”。

### 四个中文控制级别

中文界面使用：

- `观察`：记录和展示，不向代理注入建议；
- `引导`：证据满足时提供建议，不阻断；
- `守护`：客户端支持时阻断规则明确的高风险动作或未经验证的结束；
- `自动守护`：应用当前客户端支持的最强本地保护，不突破权限边界。

控件旁显示当前客户端的实际能力，例如“Codex：建议式引导，不能强制阻断”“Claude Code：Hook 支持建议与有限守护”。英文界面保留英文标签。

## 二、有用的数据工作区

### 用量与费用

页面首先回答“金额是否可知”，不再用累计 Token 作为最大视觉元素。

主结论区显示：精确费用、估算费用、未知请求数、未知原因和一个修复动作。没有价格目录时显示“费用暂不可计算”，绝不显示伪造的 0 元。

用量结构显示：未缓存输入、缓存输入、输出、推理、缓存率、每请求均值。按项目、会话、客户端、模型和日期提供真实排行。未知费用列表显示安全请求 ID、模型公开名称、Token、时间、缺失原因，并允许为公开模型选择或录入本地价格映射。价格映射保存版本、币种、生效时间和来源标签。

### 效率趋势

趋势直接读取已有 `model_requests` 和 usage 数据，不再依赖当前为空的生命周期事件表。提供最近 7/30 天请求量、失败率、P50/P95 延迟、未缓存 Token、输出 Token和缓存率。少于两个时间点时显示明确的样本说明，不绘制虚假趋势。

### 项目记忆

记忆必须是可查看和可操作的条目，而不是三个计数。

- 用户可从一条对话消息显式执行“保存为项目记忆”；
- 用户可手动新增约束、决定、验证方式或环境事实；
- 自动候选只来自安全、确定性的事实，例如反复出现的验证标签或明确失败指纹，不用额外模型推断语义；
- 候选必须经用户确认才能成为 active；
- 每条记忆显示来源、创建时间、状态，并支持确认、编辑、停用和删除；
- MCP context capsule 只返回 active 记忆，并保留来源与边界。

### 任务对比

取消“15 个样本前整个页面为空”的设计。用户可立即选择同一项目的两个真实会话做并排比较，比较请求数、失败、耗时、未缓存 Token、输出、缓存率和可用费用。

群体胜负结论仍要求每组至少 15 个匹配样本；不足时显示“还差 N 个”，只展示描述性差异，不宣称因果或赢家。对比结果按输入会话和算法版本幂等保存。

### 编辑器连接

每个客户端显示：是否安装、是否配置、是否正在活动、最后证据时间、可采集信号、反馈能力、阻断能力和具体缺口。提供明确的“修复接入”操作；该操作只应用 Agent Doctor 标记和可回滚的配置。已经运行的客户端需要重启时必须直接写明。

### 本地数据

页面显示数据库大小、请求/消息/事件/指导/记忆/对比数量、最早和最新记录时间、保留策略和下一次可清理数量。提供安全聚合导出、按会话删除、清理过期数据和全部遗忘；破坏性操作保留二次确认。数据库绝对路径不进入远程或 MCP 输出，只在认证的本地页面按需显示。

## 三、一键本地安装

仓库用户执行：

```bash
./scripts/install-local.sh
```

脚本行为固定为：

1. 检查 macOS/Linux、Go、Node 和 pnpm，缺失时给出准确安装命令并退出，不静默执行系统包管理器；
2. 执行 `pnpm install --frozen-lockfile`、嵌入式前端构建和 Go 测试的快速安装闸门；
3. 构建当前源码并原子安装到 `~/.local/bin/agent-doctor`；
4. 调用 `agent-doctor setup --yes --all --json`；
5. 安装/更新 Agent Doctor 管理的 Codex MCP 块、Codex Skill、Codex 全局指导块、Claude Code Hook 和 Claude Skill；
6. 所有外部配置先备份，只改 Agent Doctor 标记范围，重复执行保持幂等；
7. 打印哪些客户端已完成、哪些需要重启；
8. 以前台方式执行 `agent-doctor start`，自动打开仪表盘并保持服务运行。

正式发布后的远程安装仍使用校验 GitHub Release 的 `install.sh`，但安装完成后同样执行 `setup --yes --all` 并自动启动。没有可验证 Release 时不伪装远程一键安装可用。

## API 与存储边界

新增迁移保存：项目价格映射、记忆条目动作、对比结果和投影幂等键。扩展现有 loopback API，而不改变公共监听边界：所有新路由继续要求随机 Bearer token、拒绝外域 Origin、限制请求体、拒绝未知字段并返回通用错误。

前端刷新继续使用现有 SSE，不新增轮询。任何聚合为空时返回空数组和 availability/limitations，而不是 `null`、0 元或虚假健康分。

## 错误处理

- 对话保存成功但投影失败时保留对话，并记录不含原始内容的本地诊断；界面显示 guidance `error`，不影响 Codex/Claude 工作；
- 价格缺失只影响金额，不影响 Token 和效率分析；
- Skill/MCP 未加载时显示 observing/unavailable，不声称已经介入；
- 安装配置任一步失败时回滚本次已应用的管理块，保留构建产物并给出可重试命令；
- 客户端 Hook 仍保持 fail-open。

## 测试与验收

每个子项目使用 TDD：先写失败测试，再实现。验收必须覆盖：

- Codex 真实请求能产生内容安全、幂等的事件和指导；
- 零事件首页不显示“正在推进”；
- 四档控制级别中英文正确并显示客户端能力；
- 当前已有 model request 数据能驱动费用结构和趋势；
- 记忆可新增、确认、编辑、停用、删除并进入 context capsule；
- 两个会话可立即对比，群体结论仍受 15 样本门槛约束；
- 连接和本地数据页面返回真实状态与计数；
- 本地安装脚本在临时 HOME 中可重复执行，配置无重复、备份可恢复；
- 完整 Go race、vet、前端测试/构建、隐私扫描、文档检查和真实二进制烟雾测试通过。
