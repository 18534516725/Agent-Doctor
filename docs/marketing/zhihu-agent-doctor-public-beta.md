# AI 写代码最难复盘的，往往不是代码，而是这两个小时到底发生了什么

前几天我在跑一个比较长的 AI 编程任务。

开头很顺：模型读代码、找入口、改实现、跑测试。过了一会儿，熟悉的情况又出现了——它开始重复搜同一批文件，换一种说法重新解释已经确认过的结论；测试失败以后修了一轮，但没有把关键验证补齐；上下文越来越长，我也越来越难判断它究竟是在推进，还是只是在“忙”。

最麻烦的是换工具。我在 Codex 里查到一半，临时想用 Claude Code 继续。聊天记录当然还在，可新客户端并不知道：目标是什么、上一轮真正完成了什么、哪些结论有证据、哪些只是推测、最后一次测试到底有没有通过。

这也是我们做 Agent Doctor 的起点。

它不是另一个帮你写代码的模型，也不是把对话原文换个页面重新展示。它更像放在本机上的任务观察层：记录 AI 编程过程中可验证的运行证据，把“任务是否推进、有没有循环、验证是否缺失、Token 和费用证据是否完整、交接上下文是否可靠”整理成能读懂的结果，再在合适的检查点给当前 Agent 一条有边界的下一步建议。

项目目前以公开测试版推进，代码会放在 [Agent Doctor GitHub](https://github.com/18534516725/Agent-Doctor)。产品定位和后续更新也会同步在 [Agent Doctor by NexoToken](https://www.nexotoken.net/official/tools/agent-doctor?utm_source=zhihu&utm_medium=community&utm_campaign=agent_doctor_beta)。

## 为什么长任务越来越难复盘

聊天记录解决的是“说过什么”，但长任务真正需要回答的，通常是另外几类问题：

- 过去半小时有没有产生新的有效证据，还是一直在重复读取和解释？
- 模型说“已经修好”，对应的测试、构建或检查真的执行了吗？
- 这次任务用了多少 Token、花了多少钱？这个数字是账单中的精确值，还是按公开价格估算的？
- 换到另一个客户端以后，应该带走哪些上下文，哪些内容不该塞进新会话？
- 当前建议来自哪些事件，有什么限制，客户端是否真的能执行或阻止下一步？

单看一段对话，很难稳定回答这些问题。人也容易被流畅的措辞影响：模型写得很像完成了，不等于验证真的完成了；页面显示一个漂亮的 `0`，也不代表费用真的为零，可能只是根本没有账单证据。

Agent Doctor 做的事，是把“对话”和“证据”分开。

## 它实际记录什么

在支持的接入路径中，Agent Doctor 会把客户端事件归一化后写入本机 SQLite。仪表盘主要展示分析结果：任务进度、循环迹象、验证状态、会话和项目统计、响应耗时、Token、费用精度、跨客户端交接以及连接状态。完整对话属于本机私有明细，需要用户主动进入相应页面查看，不拿它充当首页的主要价值。

费用部分会明确分成三种状态：

- **精确值（exact）**：兼容的账单来源直接报告了实际扣费；
- **估算值（estimated）**：捕获到 Token，并使用带版本的公开价格目录计算；
- **不可用（unavailable）**：缺少用量、价格、币种或账单证据。

这三类不会被偷偷合成一个看起来很确定的总数。没有证据，就显示不可用。老实说，这一点不够“炫”，但比凭空给出 `$0.0000` 有用得多。

诊断也是同样的原则。一次响应慢不会直接被判成“模型降智”，某个工具调用失败也不会立刻被判成任务失控。规则会结合事件顺序、进度、验证结果、历史基线和反向证据，再输出诊断代码、严重程度、依据、限制和精度。当前规则引擎是确定性的，本地运行，不会为了分析再偷偷调用第二个模型，也不需要额外配置一把分析 API Key。

## 从 Codex 切到 Claude Code，它怎么交接

我最在意的不是保存一大坨历史，而是“下一位接手的人能不能在一分钟内进入状态”。

Agent Doctor 会生成一份有长度上限的项目交接摘要，包括最近任务目标、最后结果、已经确认的项目记忆、来源和明确限制。它不会把整段聊天直接灌进下一个客户端。交接内容会先经过同一套凭证和路径过滤，发送记录也会留在本机仪表盘中，方便知道何时、向哪个客户端交付过什么类型的上下文。

一个典型流程大概是：

```text
Codex / Claude Code / 其他受支持客户端
        ↓ 公开接口或安全 wrapper
本地事件归一化与敏感信息过滤
        ↓
本机 SQLite 证据库
        ↓
确定性诊断、费用口径、项目记忆与交接摘要
        ↓
本地仪表盘 + MCP / Hook / Skill 检查点建议
```

这里有个必须说清楚的边界：Codex 的 MCP 和 Skill 可以把建议送进上下文，但文本建议不能强制模型服从；Claude Code 的官方 Hook 在少数文档化的检查点支持阻断，但也只在对应事件和控制级别下成立。Agent Doctor 不会把“能提醒”包装成“百分之百能拦住”。

## 仪表盘不是聊天记录阅读器

首页应该先回答“项目现在怎么样”，而不是把几万字原文铺满屏幕。当前方向包括：

- 当前任务健康度与证据精度；
- 是否出现重复搜索、重复修改或长时间无新证据；
- 最近一次验证是否通过，是否存在“口头完成但没有测试”的缺口；
- 请求数、Token、平均响应、精确费用与估算费用；
- 正在活动的客户端、已发现但未连接的客户端；
- 项目记忆和跨客户端交接状态；
- 可比较任务达到最低样本量后的趋势，而不是用两个样本就宣布谁更强。

原始对话仍然可以看，因为排查时它很重要。但它应该是一个按需展开的证据入口，不是产品的全部。

## 它不会做什么

公开测试版先把边界说在前面：

- 不读取编辑器私有数据库，不绕过客户端权限；
- 不承诺所有客户端都能提供同样丰富的事件；
- 不会附着到任意已经运行的进程，实时代理路径需要通过 `agent-doctor run -- ...` 启动客户端；
- 不保存 API Key、Authorization、Cookie 或传输请求头；
- 不把缺失费用写成零，也不自动宣布某个模型“最好”；
- 不把 MCP 建议说成确定性拦截；
- 公开测试版可能仍有兼容性和界面问题，Issue 里的可复现反馈会直接决定后续优先级。

完整对话在开启实时捕获时会保存在用户自己的 SQLite 中，所以这仍然是一份敏感的本地数据。数据库不会提交到 GitHub，也不会默认上传。用户可以暂停采集、导出经过处理的聚合结果，或用 `forget` 明确删除本地数据库。

## 如何开始使用

公开 Release 完成后，最简单的入口会是一条安装命令；如果想先从源码体验，可以克隆仓库后运行：

```bash
git clone https://github.com/18534516725/Agent-Doctor.git
cd Agent-Doctor
./scripts/install-local.sh
```

安装完成后启动本地服务：

```bash
agent-doctor start
```

它会检查受管集成、启动只监听 `127.0.0.1` 的服务并打开仪表盘。要捕获一段新的 Codex 或 Claude Code 调用，用同一个命令包装客户端：

```bash
agent-doctor run -- codex
# 或
agent-doctor run -- claude
```

想先看它准备修改哪些配置，可以运行：

```bash
agent-doctor setup --json
```

想检查本地数据库、客户端发现和当前诊断：

```bash
agent-doctor doctor --json
agent-doctor diagnose --json
agent-doctor costs --json
```

## 为什么它和 NexoToken 放在一起

Agent Doctor 是 NexoToken 发起的开源工具，但它不要求注册 NexoToken 才能完成本地诊断。两者的关系很直接：NexoToken 负责长期维护、文档和产品入口；Agent Doctor 保持独立仓库、开放代码和本地优先边界。以后如果用户明确选择导入自己的 NexoToken 用量，才会补充更精确的个人费用证据，这属于可选网络动作，不是本地核心功能的前置条件。

我更希望大家把它当成一个能被验证、也能被挑错的工程工具，而不是又一个写满口号的 AI 项目。

如果你愿意试，建议带着一个真实的长任务来：跑十几分钟，故意中途换一次客户端，再检查它有没有准确说明任务进度、验证缺口和费用精度。如果结果不对，请在 GitHub Issue 里写明操作系统、Agent Doctor 版本、客户端版本、复现步骤和预期行为，但不要上传完整数据库、完整对话或任何密钥。
